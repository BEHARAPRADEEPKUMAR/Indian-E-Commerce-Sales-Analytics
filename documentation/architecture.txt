1. Project Overview

This project implements an end-to-end Indian E-Commerce Sales Analytics data engineering pipeline using Databricks and PySpark.

The pipeline follows the Medallion Architecture:

Raw CSV Files
      ↓
   Bronze
      ↓
   Silver
      ↓
    Gold
      ↓
 Analytics
      ↓
 Data Quality
2. Technology Stack
Technology	Purpose
Databricks	Data engineering platform
PySpark	Data processing and transformation
Delta Lake	Storage format
SQL	Data analysis and validation
Python	Transformation and analytics
Databricks Workflows	Pipeline orchestration
3. Data Sources

The project uses three CSV files:

customers.csv
products.csv
sales.csv
Source volumes
Customers : 40,000
Products  : 2,000
Sales     : 250,000
4. Medallion Architecture
Bronze Layer

The Bronze layer ingests the raw CSV files into Delta tables with minimal transformation.

customers.csv ──→ bronze_customers
products.csv  ──→ bronze_products
sales.csv     ──→ bronze_sales

Purpose:

Raw data ingestion
Preserve source data
Create Delta-based storage
Establish the foundation for downstream processing
Silver Layer

The Silver layer cleans and validates the Bronze data.

bronze_customers ──→ silver_customers
bronze_products  ──→ silver_products
bronze_sales     ──→ silver_sales

Typical processing includes:

Data type standardization
Null handling
Duplicate validation
Date validation
Numeric validation
Business-rule checks
Data cleansing
Gold Layer

The Gold layer contains business-ready dimensional and fact tables.

Dimensions
dim_customer
dim_product
dim_date
Fact
fact_sales

The fact table uses:

Order_ID

as the order-level grain.

6. Data Quality Layer

The final pipeline stage validates the processed data.

Checks include:

Row counts
Primary keys
Foreign keys
Critical null values
Date validation
Quantity validation
Order status validation
Negative transaction amount detection
Revenue reconciliation
Delivered units reconciliation

Final result:

Failed Checks   : 0
Warning Checks  : 1
Overall Status  : PASS

The single warning relates to 5 negative Total_Amount records, which were retained and flagged for business review.

7. Workflow Architecture

The Databricks Workflow is:

                    ┌── silver_customers ──┐
                    │                      │
bronze_ingestion ───┼── silver_products ───┼──→ gold_dimensions
                    │                      │
                    └── silver_sales ──────┘
                                             ↓
                                      gold_fact_sales
                                             ↓
                                       gold_analytics
                                             ↓
                                        data_quality

The three Silver tasks run in parallel after Bronze ingestion.

The downstream Gold processing starts after the required Silver tasks complete.
